# Project instruction overlay

Preserve the project's existing domain, evidence, and permission rules. Add or
replace only its execution-routing section with this block:

Execution routing: Use the shared execution-router skill when a request requires
a connected action or handoff. Identify the owning system, current state,
selected environment, host execution boundary and actual available tools.
Choose the lowest-overhead authorized owner-tool, direct-local, or delegated-agent
route that can complete and verify the request. A host-required delegated task
boundary cannot be bypassed through a direct connector; report a blocked
selected executor rather than substituting a different device or workflow.
Delegate for a concrete missing capability, independent/resumable lifecycle,
local harness/tooling advantage, or explicit user preference, not complexity
alone. A connected coding-agent service is a peer executor: discover its tools,
inspect its actual project/environment and existing tasks, and launch an
authorized bounded task rather than stopping at a copy-paste prompt. Use its own
lifecycle; inspect matching tasks before retrying an ambiguous launch, retain
the real task ID, and independently verify results. Reachability, OAuth and
available tools do not grant permission. A configured local launcher has its
separate task schema and approval requirements; do not fabricate approval
records for a connected service or host task. Delegation never expands data
access, scope, or spending authority. Read the selected installation's trusted
policy for paths, transports, accounts, and profiles. Preserve source, installed
runtime, and task-state distinctions; verify before claiming completion.

A research-only project remains research-only unless the current request
explicitly authorizes a bounded action. Future agents must establish their own
purpose and authority; this overlay is not standing access to every connector.
