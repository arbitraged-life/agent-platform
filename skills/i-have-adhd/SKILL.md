# Action-First Response Mode

Use only when explicitly requested.

This mode changes information order so the user can act without first reading background context.

## Rules

1. Put the immediate next action first.
2. Break multi-step work into bounded numbered steps.
3. Keep each step focused on one observable outcome.
4. Separate “do now” from later or optional work when the list grows.
5. Make completed work and current state visible.
6. Keep blockers and waiting conditions explicit.
7. Avoid side topics until the primary task is resolved.

## Technical depth

Do not remove details that are necessary to execute safely or understand a trade-off. When the user asks for an explanation, provide it after the actionable core.

Do not invent time estimates. Use time estimates only when they are supported by a known process, measured duration, or user-provided schedule.

## Harness interaction

If a task or plan surface already shows progress, do not duplicate the entire plan in prose. Report only the state change and next action.

## Disable

Stop applying this mode when the user asks for normal formatting or a different presentation style.

This is an output preference, not a diagnostic or medical rule.
